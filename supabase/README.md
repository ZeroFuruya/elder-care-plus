# supabase

Local Supabase configuration, database migrations and database tests.

- `config.toml` — local stack config (generated by `npx supabase init`, project id `eldercare-plus`).
- `migrations/` — every schema change. **Never edit an applied migration.**
- `seed.sql` — synthetic-only dev fixtures.
- `tests/` — pgTAP tests for the invariants each sprint claims (`npx supabase test db`).

## Rules (docs/01-dev-environment.md sections 8.1 and 9)

- **RLS on every table, default deny.** Caregiver sees only the active linked
  elder. Elder reads only their own linked records and may change only their own
  due dose, through a guarded RPC — never a direct table write.
- **Idempotency at the DB layer**: one `dose_events` row per schedule occurrence,
  so an offline retry cannot duplicate `taken_at` or double-decrement stock.
- The `prescription-evidence` bucket is **private**; access via short-lived signed
  URLs only.
- Service-role key is **server-only** — never in the mobile app or the repo.
- A migration ships together with its RLS policies and its tests.

## What exists today

- `bootstrap_extensions` — `pgcrypto` (care-link codes, checksums) and `vector` (later embeddings).
- `sprint1_profiles` — `profiles` for the three roles (`caregiver`, `elder`, `family_member`),
  immutable role, soft delete, and the `handle_new_user` signup trigger.
- `sprint1_care_links` — `care_links` (care-circle membership: one manager plus N view-only family
  members) and `care_link_invites` (bcrypt-hashed six-digit, single-use, 24-hour codes).
- `sprint1_rls_and_rpcs` — `audit_events` (append-only), the RLS helpers and policies, column
  grants, and the guarded RPCs: `create_elder_link_invite`, `invite_family_member`,
  `redeem_care_link_code`, `consent_to_care_link`, `revoke_care_link`, `deactivate_account`.

The mobile app still runs on SQLite and is not wired to this schema; the cutover is Sprint 1b
(`docs/01-dev-environment.md` section 11).

## Commands

```bash
npx supabase start                 # local stack (requires Docker Desktop)
npx supabase migration new <name>
npx supabase db reset              # re-run migrations + seed
npx supabase test db               # pgTAP invariants
npx supabase db push               # apply to the linked project
npx supabase db dump -f backup.sql # manual backup (Free plan has none)
```

Docker Desktop 29 (WSL2) is installed on the owner's machine and the local stack runs
(`npx supabase start`); `npx supabase db reset` applies every migration and the seed.
